How it works

From symptom names to a neural network

  1. Prepare the data. Normalize symptom names and disease aliases, merge duplicate symptom columns, reject conflicting labels, and remove repeated patterns.
  2. Separate the examples. Split the unique patterns into training, validation, and test partitions, with every category represented and no identical pattern shared between partitions.
  3. Train the network. A PyTorch multilayer perceptron maps 131 binary inputs through hidden layers of 128 and 64 units to 41 category scores. It uses ReLU, dropout, cross-entropy loss, and AdamW.
  4. Select and evaluate. Validation loss selects the checkpoint. A separate held-out report includes per-category precision and recall, macro F1, confusion matrices, and a classical SVC baseline.
  5. Handle uncertainty. Sparse inputs, unfamiliar combinations, and ambiguous model scores can return no match. Some symptoms show an urgent-care message before classification.

The rules for returning no match are demonstration heuristics. The model's scores are uncalibrated, and neither the model nor these rules have been validated for clinical decisions. Related symptom templates may still appear across partitions even after exact duplicates are removed.

The app runs a fixed trained network. It does not learn from submissions. Rebuilding the model requires explicitly running the training pipeline.
